# 클로소 크리에이티브 5-에이전트 팀 블루프린트

> **상태: 구현됨.** 에이전트 정의는 `.claude/agents/`에 존재. 오케스트레이션은 메인 Claude(나)가 수행한다.
> 왜 이 팀이 필요했나 → "클로소 디자이너를 고용한 것 같은" 아웃풋이 안 나온 이유(정답지·노하우·검증 부재)를 종합 레퍼런스·플레이북·역할 분리로 해소.

## 팀 구성 (5명)

| 에이전트 | 역할 | 근거 문서 | 주요 산출 |
|----------|------|-----------|-----------|
| **coloso-consultant** | 운영자 상담·전략 종합·브리프 | 플레이북 + 레퍼런스 + 스펙 + 프로그램 데이터 | 진단·전략·실행 브리프·노하우 |
| **coloso-marketing-strategist** | 홍보 효과 분석·채널/증빙 전략·플레이북 유지 | 마케팅 플레이북 | 전략·증빙안·플레이북 갱신 |
| **coloso-copywriter** | 한국어 카피(헤드라인·배지·CTA·증빙) | 플레이북 §2·§4 | 데이터 필드 카피 채움 |
| **coloso-ui-designer** | 클로소급 UI 구현(레포 토큰) | 디자인 스펙 + 레퍼런스 | 컴포넌트/페이지 구현 |
| **coloso-design-analyst** | 참고 사이트 종합 캡처·DNA/아키타입 추출 | 레퍼런스 라이브러리 | 아키타입·갭 갱신 |

## 오케스트레이션 흐름 (메인 Claude가 지휘)

```
운영자 요청 ("프로그램 X 홍보·디자인 해줘")
        │
        ▼
[consultant] 진단 → 전략 → 실행 브리프 → 노하우
        │
        ├──▶ [marketing-strategist] 전략·증빙 정교화 ─┐
        │                                            ▼
        ├──▶ [copywriter] 헤드라인·배지·CTA·증빙 카피 (데이터 채움)
        │                                            
        └──▶ [ui-designer] 13단 아키타입으로 구현/리디자인 (토큰 준수)
        │
        ▼
메인 Claude 통합·리뷰(스펙 Do/Don't·플레이북 §6 체크리스트) → 운영자 보고
        │
        ▼
(검증) lint/build + dev 렌더 스크린샷 → 클로소 레퍼런스/스펙과 대조
```
- 새 참고 사이트 분석이 필요하면 먼저 **[design-analyst]** 로 레퍼런스/플레이북 갱신 후 진행.
- 카피라이터·디자이너는 **병렬** 실행 가능(서로 다른 파일군).

## 협업 시나리오 예시
1. 운영자: "바리스타 직업체험 페이지를 클로소처럼."
2. **consultant**: 대상=초등/학교, 앵글=체험 재미+진로탐색, 아키타입=ProductHero+증빙3칸+듀얼CTA, 브리프 작성.
3. **copywriter**: `heroHeadline`="90분 만에 나만의 라떼아트를 완성하는 바리스타 체험", 배지=`강력추천`, 증빙=운영학교/참여학생/만족도(확인 필요 표시), CTA="상담 신청"/"프로그램 자세히".
4. **ui-designer**: `ProductHero`·`CourseCard` 재사용해 13단 골격 구현, 토큰 준수, lint/build.
5. 메인 Claude: 체크리스트 검수 → 운영자 보고.

## 검증 루프 (품질 게이트)
- 토큰 일탈(임의 색/그림자/이징) = 자동 반려.
- 전환 요소 누락 = 플레이북 §6 13단 체크리스트로 반려.
- 허위 수치/마감 = 윤리 가드레일(플레이북 §9) 반려.
- 렌더 검증은 `verify`/`run` 스킬 활용.

## 다음 단계 (범위 밖)
실제 프로그램 1개를 종단 시범 적용(consultant→copywriter+designer)해 "디자이너 고용급" 결과를 스크린샷으로 입증.
