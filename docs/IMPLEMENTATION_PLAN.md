# 재설계 구현 계획 — 작은 단위로 실제 동작까지

> 2026-09-07 · [제품 사양](PRODUCT_REDESIGN.md)의 실행 계획.
> 상태: 아래 P0~P5는 **모두 구현 대기**. 이번 변경에서는 문서·작업 규칙만 추가한다.
> 기준: master@d11ed904a73e457963eb842b9144141219264e38.

## 1. 작업 순서

P0 사실 오염 차단 → P1 원본 디자인·파일럿 계약 → P2 교육 데이터·검증 → P3 상세페이지 재현 → P4 제작·승인·발행 관리자 → P5 기존 목표 전체 연결.

사진 확보와 디자인 캡처는 데이터 설계와 병렬로 준비할 수 있다. 하지만 미검증 대량 생성, 전면 CSS 교체, 전체 프로그램 일괄 발행을 먼저 하지 않는다.

## 2. P0 — 실적·운영 사실을 안전하게 만들기

관련 요구: R02, R13, R15, R20.

### 변경 대상

- `generate-products.mjs`: 무작위 실적·자동 경력·검증되지 않은 제공 보장 생성 경로.
- `src/lib/data/products/*.ts`: 기존 생성 결과의 근거 감사.
- `heroProofStats`, 후기, 강사 경력, 기관 인정, 수료증, 가격·혜택.

### 구현 작업

1. 기존 데이터 백업과 프로그램별 감사 목록을 만든다. 실제 값과 미검증 문자열을 구분한다.
2. 생성 스크립트가 운영 데이터를 덮어쓰지 못하도록 기본 실행을 차단하거나 출력 경로를 별도 draft 영역으로 제한한다. 명시적 실행 옵션만으로 사실 검증을 우회할 수 없게 한다.
3. 근거 없는 숫자를 0이나 임의 숫자로 바꾸지 않는다. 공개 projection에서는 미검증 주장을 제외하고 관리자에 검증 과제를 남긴다.
4. 검증된 후기·실적이 없는 화면의 빈 상태를 만든다.

### 수용 조건

- 같은 입력의 재생성으로 실적 값이 변하지 않는다.
- 미승인 실적·기관 인정·자격·후기가 공개본에 포함되지 않는다.
- 실제 확인된 자료를 지우지 않고 검토 이력을 남긴다.
- 이 단계 완료 전 대량 상품 생성과 공개 발행은 하지 않는다.

## 3. P1 — 원본 디자인 계약과 첫 프로그램 정하기

관련 요구: R01, R06, R09, R16.

### 산출물

- 페이지 종류별 콜로소 reference manifest.
- PC·모바일 기준 캡처와 섹션·동작 기록.
- 실측 토큰 초안, 의도적 차이 목록, 승인 상태.
- 파일럿 `giants-shoulder-ai-literacy`의 사실·미확인·유지할 정체성 목록.

### 수용 조건

- 원본 URL·관찰 날짜·화면 조건·이미지 출처를 추적할 수 있다.
- 실제 캡처하지 않은 페이지에 captured/approved를 붙이지 않는다.
- '콜로소 느낌'이 아니라 비교할 화면과 구성 요소가 있다.
- 파일럿의 300분·5시간·6시간 관계를 수업시간/쉬는시간/전체 체류시간으로 정리하거나 미확인으로 남긴다.

## 4. P2 — 교육상품 데이터와 검증기

관련 요구: R05, R06, R17, R19, R20.

### 제안 모듈

`src/domain/programs/`에 Program, VariantRevision, Session, Activity, Objective, Outcome과 순수 검증 함수를 만든다. 새로 도입할 schema/validator 도구는 현재 package.json 및 설치 버전 검토 후 선택한다.

### 구현 작업

- 분 단위 숫자와 단위를 저장하고 화면용 '5시간' 문자열은 파생한다.
- 시간표 길이는 운영안에서 설정한다. 학교급만 보고 모든 차시를 자동 50분으로 고정하지 않는다.
- 2·4·6차시 운영안에 각각 다른 목표·결과물·준비 조건을 둔다.
- 교육 수업안과 공개 요약을 분리하여 내부 강사 메모가 외부에 노출되지 않게 한다.
- 기본 모델에 없는 legacy 필드는 승인 없이 가짜 값으로 채우지 않는다.

### 필수 테스트

| ID | 입력/행동 | 기대 결과 |
|---|---|---|
| T01 | 50분 차시에 활동 8+12+15+10+5 | 시간 검증 통과 |
| T02 | 50분 차시에 활동 합 55 | EDU-001 차단 |
| T03 | 6×50분인데 공개 요약에 수업시간 360분 | EDU-002 차단 |
| T04 | 전체 체류시간 360분, 수업 300분, 쉬는시간 60분 | 구분 표기와 합 검증 통과 |
| T05 | 목표는 있으나 활동·결과물 연결이 없음 | EDU-003 차단 |
| T06 | 온라인 제작 운영안인데 기기·계정 조건 미확인 | EDU-005 차단 |
| T07 | 6차시를 2차시로 변경 | 종속 카피·문서·추천·검증 stale 표시 |
| T08 | 프로그램 재생성 | 기존 승인본 불변, 새 draft revision 생성 |

교육 적합성은 자동 테스트 통과와 별도로 교육 담당자가 확인한다.

## 5. P3 — 상세페이지와 미디어 계획

관련 요구: R01, R04, R08, R09, R13, R16.

### 변경 후보 파일

- `src/app/products/[slug]/page.tsx`: 새 공개 스냅샷/기존 데이터 어댑터 연결.
- `_components/ProductHero.tsx`: 검증된 정보만 표시, 승인된 디자인 계약 적용.
- `_components/Curriculum.tsx`: 운영안·차시·활동·결과물 연결, 임의 배지 제거.
- 기존 `RequiredTools` 또는 대체 `DeliveryGuide`: 준비 주체와 환경 조건 표시.
- `_components/StickyBottomSummary.tsx`: 선택 운영안·요청 경로 유지.
- `src/lib/data/courses.ts`: 중복 문자열 대신 공개 projection으로 전환.

### 구현 작업

첫 페이지는 파일럿 하나에만 새 렌더러를 적용한다. 목록·탭·관련 프로그램·SEO·기존 URL을 깨지 않는다. 기준 디자인과의 차이를 고치되 모든 페이지의 CSS를 한 번에 바꾸지 않는다.

각 섹션의 이미지·영상 계획을 저장한다. 실제 결과물·현장 사진·AI 콘셉트 이미지를 구분한다. 승인된 대체 이미지가 있으면 선택형 영상 없이도 페이지를 검토할 수 있게 한다.

### 수용 조건

- 기준 레퍼런스와 PC·모바일 구조 비교표가 있다.
- 360/390/768/1440 폭에서 가로 넘침·고정바 가림·탭 위치를 확인한다.
- 키보드·터치·모션 감소 환경에서 주요 콘텐츠와 행동이 가능하다.
- 커리큘럼에 학생 활동과 결과물이 보인다.
- 준비물·학교 역할·필수 환경이 공개 화면에 실제로 렌더링된다.
- 프로그램·운영안 선택이 견적 진입 시 유지된다.
- 시각 회귀의 기준 캡처는 사람 승인 후 고정한다.

## 6. P4 — 제작실·검토·발행

관련 요구: R02, R10, R13, R15, R18, R19, R20.

### 구현 작업

- 관리자 인증과 역할: 작성, 교육 검토, 디자인 검토, 발행을 구분한다.
- 프로그램·근거·디자인·미디어·페이지·검증 화면을 연결한다.
- 단계별 GenerationRun과 재시도·취소·중복 방지·실패 기록을 영구 저장한다.
- 낙관적 동시 수정 제어로 다른 사람의 수정본을 조용히 덮어쓰지 않는다.
- 서버가 필수 검증과 승인 권한을 확인하고 발행 스냅샷을 원자적으로 만든다.
- 원자료와 학생·학교 담당자 관련 비공개 필드는 공개 응답에 포함하지 않는다.
- 변경 영향, 이전/현재 비교, 승인 취소, 이전 공개본 롤백을 지원한다.

## 7. P5 — 원래 15개 목표를 같은 데이터로 연결

관련 요구: R01~R15.

학년별 추천과 AI 로드맵은 승인된 운영안 ID로 연결한다. 체험모험ZIP과 메인 스튜디오 연출도 같은 프로그램·미디어 데이터를 사용한다. 회사 소개, 후기, 소식, 학교 사례는 출처와 공개 범위를 유지한다.

견적은 예상 계산과 정식 접수를 분리한다. 승인 단가가 없으면 금액을 만들지 않는다. 정식 접수는 저장 성공 이후 접수번호를 반환하고 담당자 알림은 별도 상태로 기록한다. 단가 버전·선택 운영안·입력 조건을 접수 스냅샷에 남긴다.

학교 안내 PDF와 강사 운영 문서는 같은 승인 운영안으로 생성하되 공개 범위를 구분한다. 이메일·문자·예약 시스템 연결은 별도 연동 계약과 승인 범위에서 구현한다.

| T17 | 같은 프로그램을 목록·상세·PDF에서 확인 | 대상·차시·수업시간·준비 조건 일치 |
| T18 | 영상 없는 프로그램 | 승인 대체 화면, 깨진 플레이어 없음 |

## 8. 매 작업 보고 형식

1. 이번에 충족한 요구 ID와 변경 파일.
2. 무엇을 왜 바꿨는지, 그대로 보존한 것.
3. 실제 실행한 테스트·명령·결과·스크린샷 경로.
4. 미실행·차단·미확인 사항.

숫자 점수·진행률만으로 완료를 보고하지 않는다. 테스트 명령은 실제 package.json의 scripts와 설치 환경에 맞춰 정하고, 실행하지 않은 `build`, `lint`, E2E, 시각 검사를 성공으로 기록하지 않는다.
